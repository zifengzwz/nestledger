# 账本导出与导入

## 入口与权限

选择左侧账本后，在概览／收支明细／分析页的顶部，或「账本管理」中点击 **导出账本**／**导入账本**。

- 个人账本仅本人可操作。
- 家庭账本拥有者及已加入的成员均可导出、导入，和查看／新增记录的权限一致。
- 导入只追加到当前目标账本，**不覆盖、不修改旧记录**；不会创建源账本、加入家庭、迁移成员或账户设置。
- 导入后的记录创建者是当前登录用户，记录编辑／删除仍遵循创建人或账本拥有者权限。

## 导出

1. 点击「导出账本」。
2. 日期可留空以导出全部，或填写开始／结束日期。日期按北京时间，包含开始与结束当天。
3. 选择 **下载 CSV** 或 **下载 JSON**。

单次最多 **5000 笔**；超过时请缩小日期范围，分次导出。

### CSV

UTF8编码、带BOM，可用Excel／WPS打开。表头如下，六列缺一不可且不能重复，列顺序可调整：

```csv
收支类型,金额（元）,分类,时间,备注,支付方式
```

- 收支类型：`收入`／`支出`。
- 金额：正数、最多两位小数，如 `12.50`；不要使用负数、千位分隔符或科学计数法。
- 分类：1–40字。
- 时间：导出为ISO8601 UTC，保留毫秒；导入支持秒或1–3位毫秒的ISO8601时间，也接受北京时间 `YYYY-MM-DD HH:mm` 或 `YYYY-MM-DD HH:mm:ss`。时区偏移最大±14:00。
- 备注：选填，最多500字；CSV引号字段支持逗号、双引号和多行内容。
- 支付方式：选填，最多40字。

Excel保存时请选择 **CSV UTF-8**，不要上传GBK编码或 `.xlsx` 文件。当前不支持XLSX格式。

为防止Excel公式注入，导出会给以危险符号开头的文本增加单引号防护；本平台CSV导入会只针对同样的危险模式还原。若原文本本身以单引号加危险符号开头，CSV可能存在歧义，**需要精确保真时请使用JSON**。

### JSON

NestLedger格式版本1的六字段收支备份，含源账本名称／类型、导出时间及记录，不包含密码、手机号、登录会话、成员、排序偏好或常用分类／图标设置。

记录字段为：`type`、`amountCents`、`category`、`occurredAt`、`note`、`paymentSource`。`paymentSource`是兼容旧数据的接口名称，界面显示“支付方式”；金额是整数分，日期为ISO8601。

空账本可以导出空备份；导入至少需要一笔有效记录。对手工修改过的JSON，导入仍按现有规则规范化日期、分类和支付方式。

## 导入

1. 点击「导入账本」，先核对顶部显示的**目标账本**。
2. 可点击「下载 CSV 模板」，填写自己的数据。**模板有一笔示例，请修改或删除，不要直接作为真实账目导入。**
3. 用「选择导入文件」选择 `.csv` 或 `.json`。文件必须为有效UTF8，文件与解析后的请求均不超过 **10MiB**，单次 **1–5000 笔**。
4. 页面显示文件名、笔数、收入／支出合计及前10笔。此时只有本地预览，**没有写入账本**。
5. 点击「校验并预览」，后端对整批格式、金额、日期、长度和账本权限进行校验；有错误会指出行号，不会写入记录或回执。
6. 显示「服务器校验通过」后，点击「确认导入」。只有这一步才追加记录。
7. 完成后记录列表与分析会更新。模板示例时间是2026年1月，若当前查看其他月份，示例不会进入当月统计，应按需要修改时间或切换分析日期。

JSON仅接受已知NestLedger格式版本1，CSV只接受上述六列。非法金额、无效日期（例如2月30日）、未知字段、超长文本、无效Unicode等会被拒绝，不会自动忽略坏行然后偷偷导入剩余记录。

## 重试与防重复

- 当前弹窗会保留同一文件的请求标识，并显示“本次导入标识”；网络失败时使用**当前文件重试**，同一次请求不会重复追加。遇到异常请保留页面显示的标识，供核查或安全恢复。
- 同一标识对应不同内容会被拒绝；切换文件或目标账本后需要重新校验。
- 关闭弹窗后重新发起一次新的导入，是新的追加操作。**不要反复导入同一备份**，除非明确希望再次追加；本功能不把所有“内容相同”的正常记录自动去重。
- 未确认导入前可以取消，不影响旧账目。开始写入后按钮会暂时禁用，避免重复点击。

## 服务端一致性边界

MongoDB为当前本机单节点实例，没有跨集合事务。实现采用整批预校验、分块有序插入、用户＋账本＋请求标识的唯一回执，以及固定字段顺序的规范化SHA256指纹。

- 明确写入失败时只清理本次生成的批次，不删除旧记录。
- `retryable`／`rollback_pending`状态可用相同标识重试，先清理本批再恢复。
- 已完成回执可安全重放；最终确认丢失时不会盲目删除可能已成功的批次。
- **处理中部分记录可能短暂可见，不承诺数据库事务级“全有或全无”。**
- 进程硬崩溃或最终确认无法判明，可能保留 `processing` 并返回 `IMPORT_IN_PROGRESS`。为避免旧执行恢复后重复写入，不自动超时接管。遇到此状态不要更换标识重复导入，应先核查服务与原执行是否已经停止，再按回执／批次核对恢复；不要删除已完成批次。

服务异常时请保留原文件与当前弹窗，不要把失败提示当作成功。生产级强事务／高可用需求需扩展MongoDB replica set和驱动事务能力。

## 验证与接口

接口及约束见[接口契约](../API_CONTRACT.md)，实际测试记录见[验证报告](VERIFICATION.md)。

- `GET /api/books/:id/export?from=ISO&to=ISO`：已授权账本的六字段备份。
- `POST /api/books/:id/import`：`requestId`、`records`及 `dryRun`，后端整批校验或幂等追加。

普通API仍为16KiB请求上限，仅导入路径放宽至10MiB；超限返回JSON错误和HTTP 413。
