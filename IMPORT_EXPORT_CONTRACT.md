# Import/export implementation contract

Preserve all existing functionality: Vue3 Chinese app, OpenResty Lua, MongoDB data, Redis session, no containers. Changes are append-only; do not overwrite old records or another account's data. Primary frontend entry is book management and may have a shortcut in the book header. Formats supported: UTF8 CSV (Excel-compatible) and NestLedger JSON backup. No XLSX dependency.

## Export API
GET `/api/books/:id/export?from=ISO&to=ISO` -> ordinary JSON envelope `{data:{format:"nestledger",version:1,exportedAt:ISO,book:{name,type},records:[{type,amountCents,category,occurredAt,note,paymentSource}]}}`.
Both personal owner and family member with access may export; all authorization enforced server-side. Optional from inclusive, to exclusive, reject invalid/inverted range and unknown query params. Stable occurredAt ascending/id ascending order. Export maximum 5000 records per request; return 422 `EXPORT_LIMIT_EXCEEDED` with Chinese explanation to narrow date range if exceeded. Do not expose users' phones, password, session data, membership, creator IDs, record IDs, or account custom settings.
Frontend uses data to download JSON or BOM UTF8 CSV through Blob URL and revokes URL after use. Use safe filename from book name. CSV headers: `收支类型,金额（元）,分类,时间,备注,支付方式`. Types exported Chinese 收入/支出. Amount exported exact integer-cent decimal string (avoid scientific notation). Time exported original ISO8601 UTC so milliseconds are not lost. Quote cells/escape quotes, support commas and multiline notes; prevent spreadsheet formula injection for textual fields (e.g. single-quote prefix dangerous leading =,+,-,@,tab,CR/newline, including leading whitespace). Import can undo only the exporter-added safe prefix for exact same dangerous patterns; document caveat; JSON backup preserves exact original text.

## Import API
POST `/api/books/:id/import` `{requestId:string,records:[same six fields],dryRun?:boolean}` -> `{data:{validated:true,count:number,dryRun:true}}` for validation, or `{data:{importedCount:number,replayed:boolean,requestId:string}}` on commit (201 fresh,200 replay).
requestId is opaque 16-64 ASCII alphanumeric/hyphen token (frontend crypto UUID), scoped to current user AND target book. Same token and same normalized payload is idempotent, must not duplicate records; different payload with same token ->409 `IMPORT_CONFLICT`. Processing/recovery collision ->409 `IMPORT_IN_PROGRESS`. Family members can import (create records) as existing creation rights allow, but cannot write inaccessible/personal others' books. Imported records' createdBy is current user; old IDs/creator/createdAt aren't honored.
Prevalidate ALL records before any insert. Same v.record restrictions: positive integer cents <=99999999999, valid income/expense, UTF8 category1-40,note0-500,paymentSource0-40,date ISO8601 normalized. Strict whitelist fields; `records` must genuine JSON array, not object; 1..5000 rows; JSON body<=10MiB and frontend file<=10MiB. Validation error400 with actionable row number; dryRun never writes business records or import receipts. Invalid/unauthorized import writes zero records.
Use MongoDB receipt collection and normalized-payload fingerprint for idempotency (hash canonical ordered tuple fields, never random Lua object-key serialization); receipt key scoped uid+bookId+requestId. Import records have generated IDs/current timestamps and internal importBatchId, not data overwrite. Insert in modest chunks; on failure perform best-effort rollback ONLY this batch and record receipt state for safe retry/recovery. Recheck book/access around commit. No claim of cross-collection transaction atomicity on standalone MongoDB. Preserve existing records under failures. Explain any unresolved dependency failures rather than claiming success.
If implementing request size override, keep ordinary API16KiB limits unchanged: dedicated nginx import location/body cap10MiB with same origin/JSON rules; generic Lua body() takes per-route max. Need failure handling for duplicate requests and concurrency.

## Frontend importer
Provide template download, CSV/JSON file picker accepting `.csv,.json` (do not evaluate contents). JSON only supported known format/version; tolerate exported backup metadata but require exactly the six supported fields per record before API; reject malformed structures/unsupported versions or unknown record fields. CSV parse quoted fields, commas, CRLF/BOM and multiline correctly; require known headers/no duplicate or unknown headers, field counts, exact money parsing, known types; empty trailing rows ignored. Time accept full ISO8601 or Shanghai `YYYY-MM-DD HH:mm[:ss]`, strict calendar checking (don't normalize invalid Feb30 to Mar2).
Show parsed record count, income/expense totals in cents, first10 or20 records, file name/target book, clear errors. Require server dry-run validation before enabling confirm. Confirm explicitly appends to current book, never overwrites; no automatic import immediately on selection. Disable duplicate commits while busy; preserve requestId for failed network retry of same file, regenerate on different file/target. Imported sourcebook name/type shown as informational only; never create/join books automatically. On success refresh records/analysis, toast; empty file states/cancel accessible focus use existing Modal. Book switch while importer is open must not send to stale book.
